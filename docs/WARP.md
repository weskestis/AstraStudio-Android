# Phase 9 — tempo-following audio

## Use

1. Select an audio clip in Session or Arrangement, then open **Warp** (also File → Warp audio).
2. Enter the recording's **source BPM**, 30–300. This is the tempo of the source, not the song's target tempo.
3. Set **Downbeat · source frame** to the original frame that should become clip beat 0. The frame must be inside the clip's trim. Audio before it remains in the original file.
4. Enable Warp and apply. Session uses the transport BPM. Arrangement and export use the enabled tempo map, including steps and ramps.
5. Pitch defaults to unchanged. Set −24 to +24 semitones independently of time. Disabling Warp restores unwarped speed and pitch while retaining the editable settings.

**Fit source to clip length** derives source tempo from the downbeat-to-end duration and the clip's existing quarter-note beat length. It does not infer beats from a recording. Check the clip length first. Audio beyond that musical loop length is not played; a loop longer than the source includes silence. Source tempo changes timing, not the stored beat length. Trim sets the length using source tempo when Warp is active and retains/clamps the downbeat inside the new range.

Edits are one Undo step. Duplicates carry all settings. Warped Arrangement splitting keeps the source's musical phase; raw audio retains its previous sample-exact split behavior. Waveform previews use the same source-beat mapping. Back closes the keyboard first, then returns to the workspace. Rotation retains the editor and entered fields.

## Engine and fidelity

Each track owns a preallocated stereo Signalsmith Stretch processor, with double-precision spectral processing and the default 120 ms analysis window / 30 ms interval. Computation splitting is enabled. Source audio is first converted to the output rate using the existing 64-tap sinc converter. A 128-frame output buffer uses the analytic tempo map to derive the required input position. Input/output latency is compensated by known-media lookahead and discarded pre-roll, so no extra transport delay is applied to other tracks.

FFT configuration, vectors and ownership changes happen off the render thread. Launch, seek, loop and ongoing processing use bounded buffers, without locks, file I/O, allocations or frees. Maximum source/target tempo ratio is 10:1 in either direction. At unchanged Session tempo/pitch, the identity path preserves unity-rate source samples exactly. Playback, resampling and offline export use the same sequencer and warp class. No extra audio file/cache is generated by enabling Warp.

Project schema and native wire are version 4. Versions 1–3 open with Warp disabled, preserving their original playback. Version 4 stores enabled state, source BPM, source-frame downbeat offset and pitch for each audio clip. Earlier APKs cannot open v4 projects; retain an older portable save if downgrade compatibility matters. The development signing certificate is unchanged.

## Evidence and limits

The dedicated native suite checks unchanged-rate sample identity, pitch at changed tempos, independent transposition, source-rate conversion, antiphase stereo, drum timing through steps/ramps, seeks, loops, downbeat offsets, exports, invalid settings and retained source samples. Allocation/free counters cover launch, seek, looping, extreme ratios and 16 simultaneous processors with mixed tonal/noise material. This establishes functional bounds, not a physical Xperia track-capacity guarantee. Kotlin tests cover persistence/migration, validation, trimming, splits, duplication and Undo. Android tests exercise the controls, rotation, Back, Undo/Redo, portable archive and native export.

This phase provides one stereo spectral algorithm and a constant source-beat grid. Detailed warp markers, automatic tempo/transient detection, Beats/Tones/Texture-specific algorithms, formant controls and a granular instrument remain planned. It is not Ableton Complex Pro. Extreme ratios can smear transients or introduce texture. Edits to source timing/pitch or base tempo re-prime the active clip; they are not guaranteed click-free live performance gestures. Hard clip/loop boundaries do not gain crossfades in this phase.

CPU cost increases with warped tracks; launch/seek pre-roll is bounded but adds a burst of work. Physical Sony timing, thermal/endurance limits, audio-route behavior and listening quality on representative songs remain unmeasured. Existing limits remain 16 tracks, 8 scenes, 64 assets and 512 MiB decoded project audio. Streaming/scaling is Phase 10. See [validation](VALIDATION.md) for the exact tested build and measured results.
