Native synthesis cases cover A4/octave/sub tuning; coherent-spectrum harmonic limits; finite wavetable interpolation; distinct audible presets; A-to-B FM; all warp modes; all four FM algorithms and all operators; all nine modulation sources; drawn LFO shape effect; beat-synced amplitude modulation; live gain edits on an existing voice; stable filter impulse responses across 8–384 kHz internal rates; preset releases at 44.1/48/96 kHz output; patch wire validation; full mailbox handling; panic and event-heap recovery retaining accepted edits; bounded 128-voice allocation; and concurrent patch publication.

The Kotlin suite additionally checks patch serialization roundtrips, version/length/NaN/range rejection, drawing interpolation in either direction and isolation of immutable patch edits. These are logic tests, not UI interaction tests.

LeakSanitizer is disabled (`ASAN_OPTIONS=detect_leaks=0`) because the traced host does not support it. ThreadSanitizer was not run. Allocation interception covers C++ new/new[], including aligned variants, in the owned renderer; it is not an audit of every internal Android or Oboe operation. Stress tests do not replace formal race detection or long-running device measurements.

The lint warnings concern the intentionally pinned SDK/dependency versions and Android backup configuration. No lint errors or warnings were suppressed to pass checks. SDK 34 remains the requested baseline, not a claim of current store-submission eligibility.

The offline audition uses eight four-second segments in factory-preset order. During the final host run, single-voice phrase rendering took approximately 1.4–3.8% of real time. Those figures vary with host load and are not Xperia benchmarks, polyphony guarantees, UI frame-rate measurements or real-time deadline certifications. Every rendered factory segment was finite, non-silent and below the master clamp.

## First Xperia test

1. Install the Phase 2 APK over Phase 1; start audio; verify Track 1 plays Liquid Riddim.
2. Hold F1 in the synth editor and adjust position, warp, filter and FM controls. Confirm the held sound changes.
3. Draw an LFO shape, assign it to filter cutoff or amplitude, then change BPM and note-retrigger mode.
4. Switch among the four FM algorithms and operator ratios/levels. Release the held note and verify silence.
5. Change tracks; verify independent patches. Close/reopen the app and verify saved edits return.
6. Change output routes, background/return, rotate the phone, and stop from the notification.
7. Compare buffer settings while playing chords. Note actual sample rate, xruns and callback load, then repeat after several minutes to expose thermal changes.
8. Test USB MIDI notes, channels and disconnect while holding a note.

Phase 3 effects, timeline workflows, recording/export, full MIDI expression, wavetable import and AI commands are not part of this validation.
